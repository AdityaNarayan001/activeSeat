# ActiveSeat — 2-DOF Active Seat Suspension Simulator

A complete simulation environment for designing, tuning, and evaluating
**active vibration control** of a vehicle seat.  The project models a
two-degree-of-freedom (2-DOF) seat–driver system with a rotary
electromechanical actuator, implements four control strategies (Passive, LQR,
H∞, Adaptive MRAC), and provides both a **desktop PyQt6 GUI** and a
**headless CLI** for running simulations.

## 1. Physical System Overview

The simulator models a **lumped-parameter quarter-car seat** consisting of
three bodies stacked vertically:

```
        ┌──────────────┐
        │    DRIVER     │   m_d  (75 kg)
        │    (body)     │
        └──────┬───────┘
               │  k₂, c₂   ← cushion (seat ↔ driver)
        ┌──────┴───────┐
        │  SEAT FRAME   │   m_s  (15 kg)
        │               │
        └──────┬───────┘
               │  k₁, c₁   ← primary suspension (chassis ↔ seat)
               │  ║ F_a     ← rotary actuator (in parallel)
        ┌──────┴───────┐
        │   CHASSIS     │   z₀(t) — road input (prescribed)
        └──────────────┘
```

### Coordinate Convention

All coordinates are **vertical, positive upward**:

| Symbol | Meaning |
|--------|---------|
| `z₀(t)` | Chassis (road) displacement — the prescribed input |
| `z_s(t)` | Seat frame absolute displacement |
| `z_d(t)` | Driver body absolute displacement |

### Degrees of Freedom

| DOF | Description |
|-----|-------------|
| **DOF 1** | Seat frame motion relative to chassis: `x₁ = z_s − z₀` |
| **DOF 2** | Driver motion relative to seat: `x₃ = z_d − z_s` |

### Rotary Actuator

The active force is generated by a **permanent-magnet servo motor** driving
a **ball-screw mechanism** in parallel with the primary spring–damper.

| Component | Function |
|-----------|----------|
| Servo motor | Produces torque `τ_m` (up to `τ_max`) |
| Ball-screw | Converts rotary motion to linear motion via gear ratio `N = 2π/lead` |
| Electrical lag | 1st-order filter: `τ̇_m = (τ_cmd − τ_m) / τ_e` |
| Friction | Viscous (`b_v · θ̇`) + smoothed Coulomb (`τ_c · tanh(α · θ̇)`, α = 100) |

The **linear actuator force** delivered to the seat is:

```
F_a = N · (τ_m − τ_friction)
```

The **reflected motor inertia** adds to the seat mass:

```
m_s_eff = m_s + J_m · N²
```

With default parameters (N = 628 rad/m, J_m = 2×10⁻⁵ kg·m²), the reflected
mass is ≈ 7.9 kg, giving an effective seat mass of ≈ 22.9 kg.  The maximum
actuator force is N × τ_max = 628 × 5 = **3 140 N**.

## 2. Mathematical Model

### 2.1 State Vector

The system is described by **5 states** (4 mechanical + 1 electrical):

```
x = [ x₁,  x₂,  x₃,  x₄,  τ_m ]
      │     │     │     │     └── motor torque (electrical lag state)
      │     │     │     └──────── driver absolute velocity ż_d
      │     │     └────────────── driver-to-seat relative displacement (z_d − z_s)
      │     └──────────────────── seat absolute velocity ż_s
      └────────────────────────── seat-to-chassis relative displacement (z_s − z₀)
```

### 2.2 Equations of Motion

**Seat frame** (Newton's 2nd law):

```
m_s_eff · z̈_s = −k₁(z_s − z₀) − c₁(ż_s − ż₀) + k₂(z_d − z_s) + c₂(ż_d − ż_s) + F_a
```

**Driver body**:

```
m_d · z̈_d = −k₂(z_d − z_s) − c₂(ż_d − ż_s)
```

### 2.3 State-Space Form

In state coordinates the ODE becomes:

```
ẋ₁ = x₂ − ż₀

ẋ₂ = (1/m_s_eff) · [−k₁ x₁ − (c₁+c₂) x₂ + k₂ x₃ + c₂ x₄ + c₁ ż₀ + F_a]

ẋ₃ = x₄ − x₂

ẋ₄ = (1/m_d)   · [c₂ x₂ − k₂ x₃ − c₂ x₄]

τ̇_m = (τ_cmd − τ_m) / τ_e
```

### 2.4 Linearised Matrices (for controller design)

Ignoring friction, saturation, and the electrical lag, the 4-state linear
model used for controller synthesis is:

```
ẋ = A x + B_u F_a + B_w ż₀
y = C x
```

Where `y = z̈_d` (driver acceleration — the comfort metric).

```
        ┌                                    ┐
        │  0        1         0       0      │
A   =   │ −k₁/ms  −(c₁+c₂)/ms  k₂/ms  c₂/ms │
        │  0       −1         0       1      │
        │  0       c₂/md    −k₂/md  −c₂/md  │
        └                                    ┘

B_u = [ 0,  1/ms,  0,  0 ]ᵀ       (actuator force input)
B_w = [ −1,  c₁/ms,  0,  0 ]ᵀ     (road velocity disturbance)
C   = [ 0,  c₂/md,  −k₂/md,  −c₂/md ]   (driver acceleration output)
```

### 2.5 Nonlinear Plant (ODE Integration)

The full nonlinear plant used during simulation includes:

- **Torque saturation**: `τ_cmd` is hard-clipped to `[−τ_max, +τ_max]`
- **Viscous friction**: `b_v · N · ẋ_s`
- **Smoothed Coulomb friction**: `τ_c · tanh(100 · N · ẋ_s)`
- **1st-order electrical lag**: `τ̇_m = (τ_cmd − τ_m) / τ_e`

For controllers with internal dynamic states (H∞, Adaptive), an **extended
ODE** is used where the controller states are appended to the plant state
vector and integrated simultaneously:

```
state = [ x₁, x₂, x₃, x₄, τ_m,  ctrl_state₁, ..., ctrl_state_n ]
```

## 3. Controller Design

### 3.1 Passive (Baseline)

No active control: `F_a = 0` at all times.  The actuator is off. This serves
as the performance **baseline** against which all active controllers are
compared.

### 3.2 LQR — Linear Quadratic Regulator

**Theory**: Minimises the infinite-horizon quadratic cost:

```
J = ∫₀^∞ (xᵀ Q x + R u²) dt
```

where `u = F_a` (actuator force) and `Q = diag(Q₁, Q₂, Q₃, Q₄)`.

**Design procedure**:
1. Solve the Continuous Algebraic Riccati Equation (CARE): `AᵀP + PA − PB_u R⁻¹ B_uᵀ P + Q = 0`
2. Compute the state feedback gain: `K = R⁻¹ B_uᵀ P`  (in force domain)
3. Convert to torque domain: `K_torque = K / N`

**Control law**: `τ_cmd = −K_torque · x`

**Tuning parameters**:

| Parameter | Symbol | Default | Effect |
|-----------|--------|---------|--------|
| `Q_diag[0]` | Q₁ | 10 | Penalty on seat-chassis displacement |
| `Q_diag[1]` | Q₂ | 700 | Penalty on seat velocity |
| `Q_diag[2]` | Q₃ | 400 000 | Penalty on driver-seat displacement (**dominant**) |
| `Q_diag[3]` | Q₄ | 700 | Penalty on driver velocity |
| `R` | R | 2×10⁻⁵ | Penalty on control force (lower → more aggressive) |

The high Q₃ value prioritises minimising relative driver–seat motion, which
directly drives driver acceleration via `z̈_d = (−k₂ x₃ − c₂ ẋ₃) / m_d`.

### 3.3 H∞ — Robust Controller

**Theory**: Finds a dynamic output-feedback controller `K(s)` that minimises
the worst-case gain from disturbance `w` (road velocity) to a weighted
performance output `z`:

```
min  ‖T_zw‖∞ < γ
```

**Mixed-sensitivity formulation**: The generalised plant `P(s)` maps:

```
Inputs:  [w, u]     — w = road velocity disturbance, u = actuator force
Outputs: [z₁, z₂, y]
  z₁ = W_perf · z̈_d    — weighted driver acceleration (comfort)
  z₂ = W_ctrl · u       — weighted control effort
  y  = x                — full state measurement
```

**Design procedure**:
1. Construct the generalised plant with static performance weights `W_perf`, `W_ctrl`
2. Call `python-control`'s `hinfsyn(P, nmeas, ncon)` to find `K(s)` and optimal `γ`
3. If `hinfsyn` fails, fall back to a robust LQR-like design via CARE

The resulting controller `K(s)` is a **dynamic compensator** with its own
internal states (typically 4, matching the plant order), which are integrated
alongside the plant using the extended ODE.

**Tuning parameters**:

| Parameter | Symbol | Default | Effect |
|-----------|--------|---------|--------|
| `hinf_gamma` | γ | 5.0 | Performance bound (lower → tighter, may be infeasible) |
| `hinf_perf_weight_accel` | W_perf | 500 | Weight on driver acceleration |
| `hinf_perf_weight_force` | W_ctrl | 0.0001 | Weight on control effort |

### 3.4 Adaptive — Model-Reference Adaptive Control (MRAC)

**Theory**: Adapts controller gains online to minimise the tracking error
between the plant output and a desired **reference model**.

**Reference model**: A 2nd-order system describing the ideal driver–seat
dynamics:

```
ẍ_ref = −2 ζ ωₙ ẋ_ref − ωₙ² x_ref
```

**Tracking error**: `e = x₃ − x_ref` (actual minus desired driver–seat displacement)

**Control law**: `F_a = θᵀ · x_mech` (adaptive gain vector × plant state)

**Lyapunov-based adaptation law** (normalised gradient):

```
θ̇ = −Γ · x_mech · (eᵀ P b) / (1 + xᵀ x)
```

where `P` is the solution to the Lyapunov equation `A_mᵀ P + P A_m = −Q_lyap`
and `b` is the reference model's input column.

**LQR warm-start**: Instead of starting from `θ = 0` (which would mean zero
control initially), the adaptive parameters are initialised to `θ₀ = −K_LQR`
(the negative of the LQR force gain), so the controller begins with
known-good performance and then **adapts online** to compensate for
nonlinearities and model mismatch.

**Internal ODE states (6 total)**:
- `x_ref`, `ẋ_ref` — reference model states
- `θ₁, θ₂, θ₃, θ₄` — adaptive gain parameters

**Tuning parameters**:

| Parameter | Symbol | Default | Effect |
|-----------|--------|---------|--------|
| `adaptive_gamma_gain` | Γ | 500 | Adaptation rate (higher → faster adaptation, riskier) |
| `adaptive_ref_wn` | ωₙ | 12 rad/s | Reference model natural frequency |
| `adaptive_ref_zeta` | ζ | 0.8 | Reference model damping ratio |

## 4. Road Excitation Profiles

Three road disturbance inputs are available:

### 4.1 Half-Sine Bump

Models driving over a single speed bump.

```
z₀(t) = h · sin(π v t / L)   for  0 ≤ t ≤ L/v
z₀(t) = 0                     otherwise
```

| Parameter | Symbol | Default | Unit |
|-----------|--------|---------|------|
| `bump_height` | h | 0.05 | m |
| `bump_length` | L | 0.5 | m |
| `vehicle_speed` | v | 10.0 | m/s |

Bump duration = L/v = 0.05 s at default settings.

### 4.2 Sinusoidal

Steady-state harmonic excitation at a single frequency. Used primarily for
the **transmissibility frequency sweep**.

```
z₀(t) = A · sin(2π f t)
```

| Parameter | Symbol | Default | Unit |
|-----------|--------|---------|------|
| `sine_amplitude` | A | 0.01 | m |
| `sine_frequency` | f | 3.0 | Hz |

### 4.3 Random Road (ISO 8608)

**Standard**: ISO 8608 defines road roughness classes by their spatial
power spectral density (PSD):

```
G_d(n) = G_d(n₀) · (n / n₀)⁻²     n₀ = 0.1 cycles/m
```

| ISO Class | G_d(n₀) [m³/cycle] | Roughness |
|-----------|---------------------|-----------|
| A | 1×10⁻⁶ | Very smooth (motorway) |
| B | 4×10⁻⁶ | Smooth |
| C | 16×10⁻⁶ | Average |
| D | 64×10⁻⁶ | Rough |
| E | 256×10⁻⁶ | Very rough (off-road) |

**Implementation**:
1. Generate white noise in the frequency domain with random phases
2. Shape the amplitude spectrum to match the ISO 8608 PSD: `|X(f)| = √(G_d · Δf)`
3. Inverse FFT to time domain
4. Compute velocity via central differences (2nd-order accurate)
5. Build linear interpolation function for the ODE solver

| Parameter | Symbol | Default | Unit |
|-----------|--------|---------|------|
| `iso_class` | — | C | — |
| `iso_speed` | v | 20.0 | m/s |
| `iso_seed` | — | 42 | — (RNG seed) |

## 5. Performance Metrics

All metrics are computed from the time-domain simulation results using
**trapezoidal integration** (`np.trapz`) for accuracy.  They are inspired by
**ISO 2631** (human exposure to whole-body vibration).

| Metric | Formula | Unit | Significance |
|--------|---------|------|-------------|
| **RMS driver acceleration** | √(∫ z̈_d² dt / T) | m/s² | **Primary ride comfort indicator** |
| **Peak driver acceleration** | max(\|z̈_d\|) | m/s² | Worst-case transient shock |
| **RMS actuator force** | √(∫ F_a² dt / T) | N | Average control effort |
| **Peak actuator force** | max(\|F_a\|) | N | Motor/mechanism sizing requirement |
| **Max seat travel** | max(\|x₁\|) | m | Stroke constraint for actuator |
| **Average power** | ∫ \|P(t)\| dt / T | W | Energy cost of active control |
| **Peak power** | max(\|P(t)\|) | W | Motor driver sizing |
| **Control effort** | ∫ F_a² dt | N²·s | Total energy-like effort measure |

**Instantaneous power**: `P(t) = F_a(t) · ẋ_s(t)` (actuator force × seat velocity)

**Comparison**: When comparing passive and active controllers, improvement is
reported as percentage change:

```
Δ% = (active − passive) / |passive| × 100
```

Negative values indicate **improvement** (e.g., −37% means 37% reduction in
driver acceleration).

## 8. Running the Simulator

### GUI Mode

```bash
python run_gui.py                          # default parameters
python run_gui.py --scenario scenarios/default.yaml   # pre-load scenario
```

### CLI Mode (Headless)

```bash
python run_sim.py                          # default parameters, saves plots to output/
python run_sim.py --scenario scenarios/heavy_driver_bump.yaml
python run_sim.py --save-plots results/    # custom output directory
```

The CLI runs the **full pipeline** automatically:
1. Passive vs Active comparison (selected controller type)
2. All 4 controllers on the same road
3. Frequency sweep (transmissibility)
4. Parameter sweep (driver mass 50–120 kg)
5. Engineering summary with saturation check

## 14. Numerical Solver Details

### Solver: Radau (default)

The default solver is **Radau** — a fully implicit Runge–Kutta method of
order 5.  It is an **A-stable** and **L-stable** method, ideal for **stiff**
ODEs.

The 2-DOF seat system is stiff because:
- The electrical time constant `τ_e = 5 ms` is much faster than the
  mechanical response (natural frequencies ≈ 3–10 Hz)
- The stiff springs (k₂ = 50 000 N/m) create fast oscillatory modes
- Coulomb friction introduces near-discontinuities

### Available Solvers

| Solver | Order | Type | Best For |
|--------|-------|------|----------|
| `Radau` | 5 | Implicit RK | **Stiff systems** (recommended) |
| `BDF` | 1–5 | Multi-step | Very stiff / DAE-like systems |
| `RK45` | 5(4) | Explicit RK | Non-stiff smooth systems |
| `RK23` | 3(2) | Explicit RK | Low-accuracy quick checks |
| `DOP853` | 8(5,3) | Explicit RK | Very high accuracy, non-stiff |

### Tolerance Settings

Default: `rtol = 10⁻⁸`, `atol = 10⁻¹⁰`.

These tight tolerances ensure accurate force reconstruction and metric
computation.  The max step size `10⁻³ s` prevents the solver from stepping
over short transients (e.g., the bump event lasting only 50 ms).

### Frequency Sweep Methodology

The transmissibility is computed empirically (not analytically) by:
1. For each frequency f in [0.5, 20] Hz (80 points):
   - Simulate `freq_steady_cycles / f` seconds (minimum 0.5 s)
   - Discard the first 50% (transient)
   - Compute RMS of driver acceleration and road acceleration
   - Transmissibility T(f) = RMS(z̈_d) / RMS(z̈₀)

This captures nonlinear effects (saturation, friction) that analytical
transfer functions miss.

## 15. Typical Results

With **default parameters** (75 kg driver, bump road, LQR controller):

| Metric | Passive | LQR | Change |
|--------|---------|-----|--------|
| RMS driver accel | 0.85 m/s² | 0.53 m/s² | **−37%** |
| Peak driver accel | 4.2 m/s² | 2.8 m/s² | −33% |
| Max seat travel | 3.1 mm | 2.4 mm | −22% |
| Avg power | 0 W | 12.5 W | — |

**All controllers comparison** (bump road):

| Controller | RMS Driver Accel | Reduction |
|------------|------------------|-----------|
| Passive | 0.85 m/s² | — (baseline) |
| LQR | 0.53 m/s² | −37% |
| H∞ | 0.32 m/s² | −63% |
| Adaptive | 0.54 m/s² | −37% |

The H∞ controller achieves the highest comfort improvement but uses a more
complex dynamic compensator. The adaptive controller matches LQR performance
on the nominal plant and can potentially outperform it when plant parameters
change (e.g., different driver masses).
